## Опис

**Vanguardl Deployment** - бот моніторингу для Discord і Telegram. Він стежить за серверами та сайтом Muhamed Abs, тримає запущених ботів на машинах і пише в канал, якщо щось пішло не так.

Підходить для:

* моніторингу серверів за хостинг-панеллю
* підтримання ботів на машинах, які зупиняються через неактивність
* сповіщень про статус у каналі Discord або чаті Telegram

Один процес запускає обох ботів і єдиний цикл перевірок. База даних не потрібна: стан зберігається в пам'яті.

---

## Можливості

* Працює в Discord і Telegram одночасно (будь-який із них можна вимкнути)
* Перевірка кожної машини через SSH: аптайм, навантаження, пам'ять і диск
* Запуск команди бота на машині, якщо вона не запущена (tmux, із запасним варіантом без нього)
* Перевірка сайту з часом відповіді
* Сповіщення, коли сервер або сайт впав, знову працює або бота довелося перезапустити
* Сповіщення надходить лише після кількох невдалих перевірок поспіль, тож поодинокий збій його не викликає
* Команда `/ai` для запитань до будь-якого OpenAI-сумісного API
* Команда `/history` з останніми комітами GitHub
* Статус у Discord показує, скільки машин онлайн
* Мінімалістичний вивід у термінал: без ключів, токенів і трейсбеків, а секрети маскуються й у файлі логів

## Команди

| Команда    | Що робить                                               |
| ---------- | ------------------------------------------------------- |
| `/start`   | про бота, пінг, творець і список команд                 |
| `/info`    | детальний статус машин і сайту                          |
| `/check`   | запустити перевірку просто зараз і розбудити сервери    |
| `/project` | про проєкт Muhamed Ads                                  |
| `/history` | останні коміти з GitHub                                 |
| `/ai`      | поставити запитання ШІ, наприклад `/ai What is Pterodactyl?` |

У Discord це слеш-команди (лише на серверах). У Telegram вони працюють у чатах і каналах.

---

## Як це працює

1. Кожні `interval` секунд (за замовчуванням 15 хвилин) монітор підключається до кожної машини через SSH
2. На машині він збирає аптайм, навантаження, використання пам'яті та диска
3. Якщо сесії бота немає, він запускає `bot_cmd` у tmux-сесії `bot` (або у фоні, якщо tmux не встановлено)
4. Також він запитує `SITE_URL` і вимірює час відповіді
5. Після 3 невдалих перевірок поспіль надсилається сповіщення, а коли ціль відновлюється, надходить повідомлення про відновлення
6. Команда `/check` запускає ту саму перевірку вручну, між перевірками діє пауза 20 секунд

## Встановлення

Потрібен Python 3.10 або новіший.

1. Клонуйте репозиторій і встановіть залежності:

```bash
pip install -r requirements.txt
```

2. Створіть `BANNED_FILES/.env` зі своїми налаштуваннями (див. нижче)
3. Скопіюйте `BANNED_FILES/machines.example.json` у `BANNED_FILES/machines.json` і впишіть свої машини
4. Запустіть бота:

```bash
python main.py
```

Має бути задано принаймні один із `DISCORD_TOKEN` і `TELEGRAM_TOKEN`.

## Налаштування

### Змінні середовища

Задаються в `BANNED_FILES/.env`:

| Змінна                   | Призначення                                                        |
| ------------------------ | ------------------------------------------------------------------ |
| `DISCORD_TOKEN`          | токен Discord-бота (якщо порожньо, Discord вимкнено)               |
| `ALERT_CHANNEL_ID`       | канал Discord для сповіщень                                        |
| `TEST_GUILDS`            | id серверів через кому; слеш-команди з'являються там миттєво       |
| `TELEGRAM_TOKEN`         | токен Telegram-бота (якщо порожньо, Telegram вимкнено)             |
| `TELEGRAM_ALERT_CHAT_ID` | чат або канал Telegram для сповіщень                               |
| `GITHUB_REPO`            | репозиторій для `/history`, у вигляді `owner/name` або повного посилання |
| `GITHUB_TOKEN`           | необов'язково, підвищує ліміт запитів до GitHub API                |
| `APINEX_API_KEY`         | ключ для `/ai` (також підходить змінна `API`)                      |
| `AI_BASE_URL`            | адреса OpenAI-сумісного API                                        |
| `AI_MODEL`               | назва моделі                                                       |
| `SITE_URL`               | сайт для перевірки (якщо порожньо, перевірка пропускається)        |
| `TIMEZONE`               | часовий пояс для годинника, за замовчуванням `Europe/Kyiv`         |
| `MACHINES_CONFIG`        | ім'я файлу з машинами, за замовчуванням `machines.json`            |

### Машини

`BANNED_FILES/machines.json`:

```json
{
  "host": "ssh.instabox.sh",
  "port": 2222,
  "interval": 900,
  "machines": [
    {
      "name": "machine1",
      "user": "YOUR_SSH_USER",
      "bot_cmd": "while true; do date >> ~/keepalive.log; sleep 60; done"
    }
  ]
}
```

| Поле      | Призначення                                                  |
| --------- | ------------------------------------------------------------ |
| `host`    | SSH-хост                                                     |
| `port`    | SSH-порт                                                     |
| `interval`| час між автоматичними перевірками, у секундах                |
| `name`    | ім'я машини в картках і сповіщеннях                          |
| `user`    | SSH-користувач машини                                        |
| `bot_cmd` | команда, яка запускається на машині, якщо вона не запущена   |

Підключення йде без пароля і без ключів: значення `user` працює як облікові дані, тому тримайте цей файл у секреті.

### Сповіщення

* **Server is down / Site is down** надсилається після 3 невдалих перевірок поспіль
* **Back online** надсилається, коли ціль знову відповідає після такого збою
* **Bot restarted** надсилається, коли бота довелося запустити заново на машині

## Безпека

* `BANNED_FILES/.env` і `BANNED_FILES/machines.json` вказані в `.gitignore`, ніколи не комітьте їх
* Токени, API-ключі та SSH-користувачі замінюються на `***` у терміналі та в `logs/bot.log`
* Термінал показує лише короткі рядки статусу. Повні трейсбеки йдуть у `logs/bot.log` (ротація, до 1 МБ на файл, 3 копії)
* Бібліотеки заглушені нижче рівня WARNING, тому вони не можуть вивести нічого зайвого

## FAQ

**Бот не запускається.**
Перевірте, що в `BANNED_FILES/.env` задано `DISCORD_TOKEN` або `TELEGRAM_TOKEN`, а `machines.json` існує і містить принаймні одну машину.

**Слеш-команди не з'являються в Discord.**
Глобальні команди можуть з'являтися не одразу. Впишіть id свого сервера в `TEST_GUILDS`, щоб отримати їх одразу.

**Сповіщень немає.**
Перевірте `ALERT_CHANNEL_ID` і `TELEGRAM_ALERT_CHAT_ID` та переконайтеся, що бот може писати в цей канал або чат. Сповіщення надходять лише після 3 невдалих перевірок поспіль.

**Чому термінал майже порожній?**
Так задумано. Подробиці лежать у `logs/bot.log`.

**Чи можна запустити лише одного з ботів?**
Так. Залиште другий токен порожнім.
